# Synapsis v0.1.3 Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Synapsis v0.1.3 as a safe local-agent release whose health endpoint, central provider/tool/persistence loop, browser UI, CI gate, and published archives are proven end to end.

**Release sequencing note:** `v0.1.2` was published from commit `3321111` while this plan was in progress. This milestone advances to `v0.1.3`; it must not replace or retag the published `v0.1.2` release.

**Architecture:** Keep ADR-006/007/008 as the runtime baseline: one supervised session process is the live authority, Concord stores durable turn snapshots, and Phoenix LiveView is the UI. This milestone adds proof and release guardrails around that architecture; it does not add remote-service authentication, a second agent loop, PostgreSQL, React, or Samgita integration.

**Tech Stack:** Elixir 1.18, OTP 28, Phoenix 1.8, LiveView 1.2, Bandit, Concord 3, Bun/Tailwind, GitHub Actions, OTP releases.

---

## Acceptance Contract

- Production binds to IPv4 loopback by default. `PHX_IP` is the explicit opt-in for another address.
- `GET /api/health` is green after a normal release boot and reports only supervised runtime components that actually exist.
- A deterministic test proves create session -> mocked provider tool request -> permission/execution -> second provider response -> durable snapshot -> worker restart/rehydrate, without duplicate tool execution or messages.
- Every LiveView form using `phx-change` has a stable unique ID, and tests raise on future missing IDs.
- Compatible fixes for known HIGH-severity HTTP/WebSocket dependency advisories are locked and the full suite remains green.
- Pull requests, pushes to `main`, and release publication all run the appropriate full test and asset gates; release automation contains no PostgreSQL service.
- The orphaned `Synapsis.Harness.*` reducer and its tests are removed; historical harness/PostgreSQL/React plans are visibly superseded.
- The four v0.1.3 platform archives have the exact requested version; the four service/install files remain separate release attachments. The current-platform archive installs into a temporary prefix, binds only to loopback by default, returns green health, and creates a session.

## Guardrails

- Run GitNexus upstream impact analysis before changing or deleting any indexed symbol. Stop and warn before HIGH/CRITICAL edits.
- Use public APIs in the vertical test; do not reach into Concord keys or private worker state.
- Provider behavior in tests is deterministic and local; never call a real provider API.
- Use `Port`-backed existing tool execution paths; do not introduce `System.cmd` into application code.
- Preserve unrelated files and keep commits split by logical scope.
- Run `graphify update .` after code changes and `gitnexus_detect_changes` before every commit.
